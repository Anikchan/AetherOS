## 1. What changed

### Pack D recorders now run in the daemons

| Recorder | Crate / module | Cadence | Persisted file |
| --- | --- | --- | --- |
| Network accounting (`NetworkRecorder`) | `powerd/src/pack_d.rs`, called from `PowerDaemon::tick` | every powerd tick (15 s default) | `<state_dir>/pack-d-network.json` |
| GPU fdinfo (`GpuRecorder`) | `lifecycled/src/pack_d.rs`, called from `Daemon::sample_pack_d` (daemon loop) | 30 s (`GPU_SAMPLE_INTERVAL_SECONDS`, D10 §3) | `<state_dir>/pack-d-gpu.json` |

- Buckets are hourly, retained 8 days, and reloaded on daemon start, so the App
  history window sees history recorded while it was closed.
- The powerd network sample runs before the battery read, so a machine without a
  battery (or a failing UPower read) still fills the buckets; that early-return
  path also persists on the 300 s cadence.
- The snapshot parser, delta rates, GPU fdinfo parser and busy-share maths moved
  from `apps/taskmanager/src/pack_d.rs` into the daemons that own the loops.
  `apps/taskmanager/src/pack_d.rs` re-exports them (public API unchanged), keeps
  `AppCpuTime`, `apply_gpu_detail`/`apply_network_totals` and `PackDContract`
  (which now publishes a `recorders` list naming the two daemons).
- Per-app GPU attribution reads `/proc/<pid>/cgroup` and uses
  `lifecycled::identity::app_id_from_scope` (also re-exported by
  `taskmanager::manager`), so a system process holding a DRM fd is skipped
  rather than counted.
- `aether-taskmanager --pack-d-history <file>` loads the daemon's network
  buckets into the App history tab; `--tab app-history` and `--render` use them.
- New `NetworkSourceStatus` / `GpuSourceStatus` are the daemon-side states;
  `PackDStatus` stays the view-side union with `From` conversions.

### Service executor behind an explicit confirm

- `SystemdDbusExecutor` builds `busctl call org.freedesktop.systemd1
  /org/freedesktop/systemd1 org.freedesktop.systemd1.Manager
  StartUnit|StopUnit|RestartUnit ss <unit> replace`; `dry_run()` records the
  vector, `system()` spawns it.
- Only `--service-action UNIT start|stop|restart --yes` reaches `system()`;
  without `--yes` the CLI prints the plan and `SERVICE_ACTION_PLAN_OK`.
- `polkit/org.aether.taskmanager.service-action.policy` defines
  `org.aether.taskmanager.service-action` with `auth_admin` on
  any/inactive/active and no retained answers. It is generated by
  `polkit_policy_xml(&contract)`, printed by `--polkit-policy`, and compiled in
  with `include_str!` so a test (and `make check-service-action-policy`) fails
  if the shipped file and the contract drift.

## 4. Hardware-gated (not verified here)

1. **eBPF accounting attach + map dump** to `/run/aether/pack-d/net-accounting`
   on AetherOS — the recorder parses fixtures only.
2. **DRM fdinfo validation** on the reference Intel (i915) and AMD (amdgpu)

   S1's `os-build/buildroot/` territory; the file and its generator are here).

## 5. Notes / follow-ups

- The CPU-time column still integrates from the Activity Manager's 1 s samples,
  so it fills only while the window samples; a daemon-side CPU recorder is a
  natural follow-up if the window is expected to stay closed.
- `AppNetworkHistory::session_total` (Processes tab) is per-daemon-run by design
  and is not persisted.
- `f64::sum` starts at `-0.0`; the App history summary now normalises an empty
  total to `0.0` so the report cannot read "-0.0 Wh".
